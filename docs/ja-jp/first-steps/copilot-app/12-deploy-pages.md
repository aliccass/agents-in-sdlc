GitHub Pages で Space Quiz をデプロイして、誰でもアクセスできるようにします。Copilot はワークフローを準備し、デプロイを案内できますが、変更をレビューしてサイトが公開されたことを確認するのはユーザーの役割です。

このレッスンでは、次の操作を行います。

- Copilot に GitHub Pages のデプロイ構成を依頼します。
- マージする前にワークフローとプル リクエストをレビューします。
- デプロイを確認し、公開されたサイトを検証します。

## シナリオ

Space Quiz はすでに GitHub リポジトリにありますが、手軽に試す方法が必要です。GitHub Pages を使って単一ファイルのサイトを公開すると、サーバーやランタイム依存関係を追加せずに、公開 URL からアクセスできるようになります。

## Copilot にデプロイの準備を依頼する

> [!WARNING]
> プル リクエストの作成によってコードがコミットおよびプッシュされることがあります。このプロンプトを送る前に、承認設定と送信先のリポジトリを確認してください。**Approve all** が有効な場合、別途確認を求められるとは限りません。

`space-quiz` の Copilot app セッションで、次のプロンプトを送信します。

```plaintext
このリポジトリを GitHub Pages で公開する準備をします。変更が既定のブランチに反映された後、必要に応じてサイトをビルドし、GitHub Pages にデプロイする GitHub Actions ワークフローを作成します。README がまだない場合は、アプリの説明とローカルでの実行方法を記載した README を追加します。これらの変更を含むプル リクエストを作成し、そのリンクと必要な Pages の設定や権限を報告します。マージ、自動マージの有効化、Pages 設定の変更、デプロイは行いません。停止して、私のレビューを待ちます。
```

## ワークフローとプル リクエストをレビューする

1. リポジトリに README がない場合に限り、README が追加されていることを確認します。
2. ワークフローのビルドとデプロイの手順、トリガー、権限など、プル リクエストの変更をレビューします。
3. マージされていないプル リクエストではなく、既定のブランチからデプロイされることを確認します。
4. 必要な修正を依頼し、更新された diff をレビューします。マージを承認する前に、必須のプル リクエスト チェックがすべて成功するまで待ちます。

## マージとデプロイを承認する

> [!WARNING]
> 次のプロンプトは、レビュー済みのプル リクエストのマージ、リポジトリの Pages 設定の変更、サイトの公開をエージェントに許可します。レビューを完了し、リポジトリとプル リクエストを確認してから送信してください。承認設定によっては、追加の確認なしにこれらの操作が実行されることがあります。

`<PR_NUMBER>` をレビューしたプル リクエスト番号に置き換え、次のプロンプトを別途送信します。

```plaintext
このリポジトリのプル リクエスト <PR_NUMBER> をレビューし、マージとデプロイを承認しました。GitHub Actions を使って GitHub Pages を有効にし、必須チェックの成功後に限り、そのプル リクエストをマージしてください。デプロイが成功するまで監視し、公開された Web サイトの最終 URL を報告してください。Pages の有効化やマージの権限がない場合は、私が承認または実行する必要がある内容を正確に伝えてください。サイトが公開されるまで成功したと報告しないでください。
```

## デプロイを確認する

1. GitHub Actions のデプロイ実行が成功するまで確認します。
2. 表示された URL を開き、Space Quiz が読み込まれることを確認します。

エージェントが Pages の有効化やプル リクエストのマージを実行できない場合は、提示された具体的な手順に従ってください。デプロイが成功し、公開サイトが読み込まれるまで、タスクを完了扱いにしないでください。
